02今日主线

第2天把商品和订单分开，第9、10天已按商品编号关联。现在固定商品1有两单、商品2有一单、商品3无订单，从每一次配对推出结果，再看给查询起名与逐行控制分别改变什么。

01

内连接与外连接的结果

固定三件商品与三张订单。订单101、102的product_id都是1，订单103的product_id是2。ON products.id=orders.product_id要求商品编号等于订单引用编号；一行连接结果代表一对记录，不是每件商品固定输出一次。

商品1分别配到订单101、102，得到两行；商品2配到103，得到一行；商品3没有匹配。INNER只保留成功匹配，共三行。LEFT保留全部左商品，所以再给商品3补一行，订单列填NULL，共四行。补NULL发生在结果中，不是原订单表新增一张空订单。

RIGHT对称地保留全部右行，也可交换两表改成LEFT。ON决定配对，WHERE再筛结果。比如LEFT得到的商品3订单列为NULL，在WHERE要求orders.id>0不成立，就删掉这行；若要保留无订单商品，不应随意加这种右列过滤。

全外连接

全外连接保留两边未匹配行。MySQL 8.4没有原生FULL OUTER JOIN，可用适当联合查询模拟并处理重复。不同订单的重复名称不能直接用DISTINCT删除。

02

自连接与交叉连接

员工表只有两行：小李id=1、manager_id=2；小王id=2、manager_id=NULL。要找每个员工的经理，同一表要作为员工e和经理m两个角色，称为自连接。e、m是本次查询的别名，不是另建两份员工表。

对员工小李，e.manager_id=2，去经理角色中匹配m.id=2，找到小王；对员工小王，manager_id为NULL，没有经理匹配。用LEFT保留小王，在经理列补NULL。条件应是e.manager_id=m.id，不是把e.id与m.id相等来给员工配自己。

“自连接”说明表来源，“LEFT”说明保留规则，可以同时成立。若需求是两种颜色各配两种尺寸，就不需要引用条件，而是保留全部组合，叫交叉连接或笛卡尔积：红配S、M，蓝也配S、M，共四行。

03

视图：给查询起一个名字

视图保存查询定义，用名称封装过滤或连接。底层实际表叫基表；普通MySQL视图结果由基表与读取视角决定，不独立保存固定结果。

CREATE VIEW available_products AS SELECT id, name, stock FROM products WHERE stock > 0;

基表库存10、0时，视图只有第一行；第二行改3并提交，再用能看见此次提交的视角查询，出现两行。不是另往视图复制数据。

部分简单单表视图可更新，修改映射到底层行；聚合、GROUP BY等通常不可更新。把“水的数量2”改3，没有唯一对应的基表行修改。

接口边界

WITH CHECK OPTION要求通过视图写入的行仍符合条件。创建视图不会自动收回基表访问权，也不是自动性能缓存。

04

集合操作与游标

若只求库存10、2的合计，SUM(stock)直接得到12，不必控制每次取哪行。另一种需求是已有一个“单件库存核对”过程，要依次取商品、交给它处理、处理完再取下一件；假设该过程以5件为补货目标，库存10记录“无需补货”，库存2记录“缺3件”。

存储程序是保存在数据库服务器端的SQL逻辑。游标是其中逐行读取查询结果、记住下一取行位置的机制：OPEN打开结果，FETCH取一行，把本行的id、stock交给核对过程；处理后再FETCH，结果耗尽时处理结束并CLOSE。这里认识控制过程，不编写完整存储程序。

FETCH本身只取值，不会自动补货或更新库存。MySQL存储程序游标只读、不可滚动，程序仍可另外执行UPDATE；循环在服务器端，不意味每次FETCH都有客户端网络往返。能用集合SQL清楚表达的任务通常优先用集合，不因这个小例就判定必须写游标。

03SQL短练习

UNION、UNION ALL与视图查询

UNION把两段查询结果纵向接起来，并去除重复行；UNION ALL保留重复。两段必须选相同列数，对应位置的含义与类型应兼容。JOIN是横向配对，UNION是纵向拼结果，不能互换。

SELECT name FROM products WHERE id IN (1, 2)
UNION ALL
SELECT name FROM products WHERE id = 4;

第一段SELECT输出水、面包，第二段输出水。UNION ALL把它们接成水、面包、水三行；换UNION会合并相同的水，剩两行。这里只选name，去重针对所选整行；若多选其他列，就要整行全部相同才合并。

练习已预建available_products视图，其定义为选出stock>0的id、name、stock；可直接SELECT查询，不需输入CREATE VIEW。

04理解自测

用自己的话回答，再对照参考解释。

1 / 3件商品，商品1有2单、商品2有1单、商品3无订单：INNER与LEFT各几行？

查看参考答案

INNER为3行：商品1两行、商品2一行。LEFT为4行，再保留商品3并把订单列补NULL。连接按匹配对产生行，不保证结果行数等于左表行数。

2 / 自连接与LEFT JOIN互斥吗？

查看参考答案

不互斥。自连接表示同一表扮演两个角色；LEFT表示保留左方未匹配行。员工与经理可使用自左连接。

3 / LEFT补给商品3的NULL订单行，是原订单表里多了一行吗？

查看参考答案

不是，商品3没有匹配订单，LEFT在本次连接结果里保留它并把右方列补NULL。INNER不输出它；如果WHERE再要求订单id>0，该NULL行不满足条件而被筛掉。

4 / 视图是否保存固定数据且都能更新？

查看参考答案

不是。普通视图保存查询定义，结果由基表生成；可更新取决于能否映射到基表行。聚合等视图通常不可更新，也不是自动性能缓存。

5 / 为什么SUM库存不必写游标循环？

查看参考答案

集合聚合已清楚表达需求。游标逐行FETCH用于需要过程控制的存储程序，带来结束处理和资源管理，不是所有SQL操作的必经步骤。
