02今日主线

SELECT name FROM products WHERE id=2要求返回编号2商品的名称“面包”。今天跟着这一条查询，看文字怎样变成取行操作，以及为什么相同查询有时需要读磁盘、有时不需要。

01

服务层与存储引擎

商品表products中，编号1叫“水”，编号2叫“面包”。SELECT name FROM products WHERE id=2;表达的需求是：找到编号2这一行，取它的name。结果应是“面包”，但SQL没有写数据的位置和取行步骤。

发出SQL的命令行工具或网站后端叫客户端；接收它的是MySQL服务器。服务器内，理解SQL并安排操作的部分称为服务层，负责实际存取表记录的部分称为存储引擎。本例商品表选择InnoDB引擎。

这是同一次查询的来回：服务层向InnoDB请求编号2的记录，InnoDB交回记录，服务层从中取name并返回客户端。两层不是两个数据库，也不是两份商品；ENGINE = InnoDB是为表选择负责存取的引擎。下面仍沿这次请求拆开服务层的安排。

02

分析、优化与执行

服务层首先检查products表、name与id列能否识别，SQL语法是否成立，这叫分析。若把name写成不存在的nam，就在这里返回未知列错误，还没有正常的取行请求。

分析通过后，找编号2可以逐行检查，也可以利用事先按编号组织的查找结构直接定位；这种结构叫索引，第4天展开它的内部查找。优化器比较可用办法的估计成本，选出执行计划，即本次查询的操作安排。计划选好不等于记录已取到。

执行器按计划调用引擎，取得符合条件的记录，再产生name结果。改查id=9，若表中没有9，分析仍可通过，执行结果为零行；它与“nam列不存在”的失败位置不同。

本课假设连接认证与权限检查已通过。下一节保持合法的id=2查询不变，只检查引擎从哪里取得数据。

旧查询缓存与页缓存

整条SQL结果缓存在MySQL 8.0起已移除。InnoDB缓冲池缓存页，命中不会省掉语句处理。

03

数据页与缓冲池

InnoDB把记录组织在数据页中，一页是一起管理和读写的一块数据，可装多条记录，通常为16KB。本例页P装着商品1“水”和商品2“面包”：取商品2的name，需要先取得P，再在P中找到商品2。

缓冲池（Buffer Pool）是InnoDB在内存中缓存数据页和索引页的区域。页P已在其中叫命中；不在叫未命中，要从磁盘把P读入。下面磁盘与内存是两个位置，P是同一个页的磁盘内容与内存副本。

两种条件都返回面包，服务层都处理同一条SQL，引擎都从页中取记录；省掉的是本次从磁盘取P。查水时读入的也是P，随后查面包可能复用整页，而不是复用上一条SQL的结果。

内存有限，P以后可能被替换。修改后尚未写回磁盘的页叫脏页，例如内存库存8、磁盘库存10。第9天从这个具体状态解释崩溃后怎样保住提交结果。

04

InnoDB与MyISAM

取行路径以外，引擎还决定修改能得到哪些保证。购买一件商品要扣库存并写订单，规则是两步都成功才算买成。事务把一组修改按共同提交或撤销边界管理；尚未提交时，ROLLBACK请求回滚，即撤销修改。

固定库存10，同样先扣1得到9，再让订单写入失败。程序主动执行ROLLBACK：InnoDB可撤销同一未提交事务的扣减，回到10；MyISAM不支持事务回滚，不能靠这条命令把已写的9找回来。

InnoDB是MySQL 8.4默认引擎，支持事务、外键与崩溃恢复，并使用记录级锁等机制；MyISAM主要用表级锁。这里比较业务需要的保证，不按“读多写少”给速度排名。第7天会亲手比较两步共用与不共用事务边界。

索引与全文检索

两种引擎的索引叶子组织在第5天对照。InnoDB也支持全文索引，不能用“只有MyISAM支持全文”选择引擎。

03SQL短练习

组合条件与NULL

AND要求两边同时成立，OR要求至少一边成立，NOT否定条件。混用时用括号表达分组；AND通常先于OR结合。

SELECT name FROM products WHERE price <= 5 AND stock > 0;
SELECT name FROM products WHERE (name = '水' OR name = '面包') AND price < 5;

NULL表示值未知或缺失，不是0。用IS NULL和IS NOT NULL检查；stock = NULL不是正确判断。WHERE只保留条件为真的行；对NULL做普通比较通常得到未知，NOT也不会把未知变成真。

MySQL日期函数

SELECT NOW(), CURRENT_DATE();

MySQL中NOW()返回当前日期和时间，CURRENT_DATE()只返回日期；受会话时区影响，NOW()通常在同一语句内保持一致。SQLite的对应名称不同，这两个MySQL函数只作语法阅读，不放入离线判题。四道短题只练条件与NULL。

SQLite离线练习，不是MySQL机制实验。

04理解自测

用自己的话回答，再对照参考解释。

1 / 服务层和引擎是两个数据库吗？

查看参考答案

不是。它们是服务器中的不同职责层。服务层理解和安排SQL，引擎管理表数据并提供存取接口；客户端是发请求的程序。

2 / SQL合法就一定会得到结果行吗？

查看参考答案

不一定。合法只说明能够处理；WHERE可能没有匹配行，权限等检查也可能失败。优化器还需要为合法查询选择执行计划。

3 / 页P已在缓冲池时，服务层分析和引擎取记录都可以省掉吗？

查看参考答案

不能。省掉的是本次从磁盘取P；服务层仍处理语句，引擎仍从页里取所需记录。缓冲池不是整条SQL结果缓存。

4 / MyISAM修改后能用ROLLBACK撤销吗？

查看参考答案

不能依靠事务回滚撤销MyISAM已写入数据。InnoDB才支持这里描述的未提交事务回滚；选择引擎要看所需能力而非简单读写比例。

5 / stock未知时，stock=0与stock IS NULL会怎样？

查看参考答案

stock=0得到未知，不被WHERE保留；IS NULL为真，会保留。NULL不是库存0，条件判断与实际无库存要分开。
