02今日主线

同一批商品可以按编号查，也可以按名称查。今天把商品行和这两条查找路径放在一起，检查找到名称后是否已经拥有查询需要的全部列，再看增加索引和插入新行的代价。

01

聚簇索引与二级索引

今天固定四件商品，id为主键。InnoDB商品表的行就在按主键组织的树叶子里，不是先查树再去另一份商品文件。查id=1，沿主键树到叶子，就能取得这行的name、price、stock。把行数据组织在索引叶子中的方式叫聚簇索引。

为按名称查找，可在建表或建索引定义中声明INDEX(name)：它表示name索引，不是可单独运行的SELECT。这是同一批商品的额外查找结构，称为二级索引。它的叶子保存name与主键id，不另存完整商品行；两个“水”对应id=1、4，仍是原来那两件商品。

因此按名称找到(水,1)时，已经知道要哪件商品；若还需stock，就要拿id=1去主键树里的那一行取。下一节只改变所选列，检查这第二段路是否必要。

没有主键或使用MyISAM

InnoDB选合适的非空唯一索引，否则生成内部行标识来组织聚簇树。MyISAM把行另存在数据文件，索引项提供记录位置，按位置读文件，不是再访问InnoDB式主键树。

02

回表与覆盖索引

固定刚才的主键树与name二级索引，运行SELECT id,name FROM products WHERE name='水';。找到(水,1)、(水,4)后，条件与所选列都已在索引项里，可以得到两行结果。这种索引对本次查询够用的关系叫覆盖索引。

把SELECT改成id、name、stock，name条件没有变，但stock不在二级叶子。必须用1、4分别访问主键树，补取10、6，再组成结果。由二级项中的主键去聚簇树取缺失列，叫回表；图中两条连线分别对应两件商品，不是把id当成页地址。

若建立(name,stock)索引，也能让它提供本次所需列，但项会更宽，写入需维护更多信息。“覆盖”不表示某种单独索引声明：同一个普通索引，可以覆盖一条查询，却不覆盖另一条。

覆盖与可见性

这里比较为补列而回表的工作。第9天的MVCC可见性检查仍可能访问聚簇记录，覆盖不代表任何情况下都绝不访问主键树。

03

主键宽度与自增编号

自增主键用数据库生成的递增编号识别行，例如id BIGINT AUTO_INCREMENT PRIMARY KEY。主键负责唯一识别，自增负责生成值。自增值可以跳号，回滚或删除不保证连续。

聚簇树按主键排序，新编号通常落在右端。下面固定同一组页、三次插入和足够空位：连续9、10、11都访问P3；分散2、9、6分别访问P1、P3、P2。能够反复用同一目标页，叫局部性。

这解释了顺序插入常见的缓存与维护收益，不代表永不分裂：页满仍需调整，集中写同一处也可能竞争。

主键宽度是另一成本。二级索引都携带主键，长字符串会在多棵树中重复占空间。短、稳定的主键通常有利；改主键也会牵动二级定位信息。

编号边界

最大id不是订单总数，也不保证跨独立数据库唯一。

04

索引用途与命名维度

UNIQUE(name,price)是建表等定义中的索引声明片段，要求非NULL的名称与价格组合不重复，同时以两列组织查找。这一个索引可以同时拥有几个称呼，不能把它们当互斥选项。

唯一说约束；联合说用了多列。在id为主键的InnoDB商品表中，它又是二级索引；若查询只取name、price、id，它还覆盖这次取列需求。四个称呼各回答不同问题。

其他用途

全文索引服务文本检索，空间索引服务几何数据。索引合并是组合多个索引访问结果的策略，不是索引声明。

03SQL短练习

LIKE、IN与BETWEEN

LIKE按模式匹配字符串，%表示任意长度字符，_表示单个字符。IN列出候选值，BETWEEN表示包含两个端点的范围。

SELECT name FROM products WHERE name LIKE '水%';
SELECT id, name FROM products WHERE id IN (1, 3);
SELECT name, price FROM products WHERE price BETWEEN 3 AND 5;

IN可简化同列的多个等值OR；BETWEEN 3 AND 5包括3与5。模式的大小写等比较细节受数据库与排序规则影响。本课用中文小值练结构，不用SQLite推断MySQL字符串索引的性能。

04理解自测

用自己的话回答，再对照参考解释。

1 / 商品行放在哪棵树，name树中的(水,1)又指向什么？

查看参考答案

InnoDB商品行就在按主键组织的聚簇树叶子里。name二级项保存名称和主键1，指向同一件商品；若要stock，用1去主键树取缺少的列，不是另一份商品。

2 / name索引已含主键id，查询多选stock为何可能回表？

查看参考答案

id和name已在二级索引项里，stock没有。为取stock，要用查到的id访问主键树；覆盖与否由本次所需列决定。

3 / 自增主键为什么常用，能否保证不跳号？

查看参考答案

常用因为短键、稳定及通常向较右侧插入，便于索引维护；不能保证连续，回滚与删除等会造成空洞，也不保证跨库唯一。

4 / 唯一索引与联合索引互斥吗？

查看参考答案

不互斥。唯一描述约束，多列描述列数，例如UNIQUE(name,price)同时符合两者。覆盖与聚簇又是别的维度。

5 / BETWEEN 3 AND 5是否包括3和5？

查看参考答案

包括两个端点。IN列候选值；LIKE使用模式，不是相同范围运算。
