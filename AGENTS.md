# MySQL course development

Before creating, editing or reviewing a lesson, read `docs/LEARNING_CONTEXT.md` and `docs/REQUIREMENTS.md`. Before delivery, apply the per-section content checklist in REQUIREMENTS.md against the revised day-one pilot; fix each omission rather than treating passing tests as editorial approval.

1. Maintain the approved twelve-day roadmap and all 55 source mappings. Review all twelve days, including days one and two, when a full-course review is requested. Prior acceptance is history, not an exemption: fix substantiated defects without gratuitously rewriting accepted material. Work in this repository; preserve sibling courses. Commit, push or publish course files only with explicit authorization for the current handoff; learner records remain private.
2. Edit authoritative sources, then run `python3 build.py`, its `--check` mode, and the Node tests. Generated HTML is an output, not an editing target. Use relative paths from the project root; learning must work from a single HTML file without an account, server, CDN or network service.
3. Preserve stable course/topic IDs, separate study/review records, topic notes, manual time tracking, five self-assessed understanding questions and three exit checks. SQL exercises provide feedback and retries but do not gate completion. Learner records are browser-local and move through JSON export/import; never commit them.
4. Teach MySQL/InnoDB mechanisms independently of SQLite. Follow the causal reasoning and bounded interaction criteria in REQUIREMENTS.md. Use one or two mechanism-specific interactions per day, with clear static comparisons elsewhere. Introduce only needed prerequisites. Day seven is a parallel transfer comparison, not a universal template. Label source mappings as website knowledge points. Keep authoring/audit commentary out of learner prose.
5. SQLite executes basic SQL exercises on four-row datasets. Include the engine label and vendor license. A successful query/result match is not evidence of mastery. Verify source anchors and current MySQL facts; mark necessary supplements and corrections in the fact-check document. Add a substantive lesson only when its content, diagrams, SQL fixtures and assessments pass validation.
