# 课程验收要求

1. 最新用户要求从第1到第12天重新完整顺序审读，并独立检查文字、页面、交互及代码。第1、2天此前的认可不是免检或禁止修复的理由；有确切缺陷就定点处理，没有问题则不为改而改。各天均须有完整正文、图示、练习与自测，保留已批准路线、SQL主题和精确网站知识点映射；交付前完成逐节内容审读，不以全量生成代替质量验收。
2. 全课分为五个独立环节：01回忆检查、02今日主线、03SQL短练习、04理解自测、05收尾记录；目录、正文和手动计时分类保持一致。每天预算为75分钟：回忆3、主线45、SQL15、自测与收尾合计12分钟，最后两项不固定拆分。计时仍如实记录实际用时，不缩放旧记录或强制封顶。保留三个课程问题、五道文字作答与自评、三项收尾、独立知识点笔记、反馈上下文和导出交接。第1、2天只修有依据的缺陷，保留其已认可结构和交互；第3–12天每课四个原理知识点，使用1–2个必要交互，其余为清晰静态对照。SQL独立于主线，不强行与当天原理同题材。
3. SQL区使用小数据集，每天3–4道短题，真实SQLite执行，支持运行、语法反馈、结果表、提示、答案、独立重置；输入草稿进入学习记录。查询结果容许等价写法和未指定顺序下的行重排，保留重复行意义。增删改题比较操作后的完整表和受影响行数；每题只运行对应的一条语句，每次重建初始数据。执行在可终止的Worker内，限时和限输出；初始化失败提供可读错误。
4. 单文件HTML可从file://直接打开、断网使用。打包全部SQLite JS/WASM和许可证，无CDN、fetch依赖。MySQL的CHAR/VARCHAR、键和非关系型概念依据官方资料核验，不能借SQLite的行为冒充MySQL实测。
5. 记录的课程ID、保存键和导出文件名独立于network-course；移植不会清理或覆盖计网的记录。study/review记录隔离。完成仅检查已有5题作答与自评、3项收尾，不检查SQL正确率。
6. 检查构建、55条覆盖、逐题来源锚点、全部图示情形、SQL正确和错误输入、草稿恢复、笔记迁移、未制作课程防护、桌面/手机布局及离线打开。文件总量限制须容纳当前字段协议允许的最大合法导出，包括JSON转义膨胀；验证导出再导入、超限读取前拒绝、超长字段拒绝及取消覆盖保留原记录，不靠截断合法笔记闭合迁移。不修改计网，不提交或推送个人记录；课件源码的提交、推送或发布须有当次明确授权。
7. 正文按概念总览、定义、解释、例子、必要边界组织；这是内容依赖顺序，不是逐节照搬的文案模板。标题直接命名知识内容，不写“先定义、再来看”等教学意图旁白；删掉紧邻的重复说明，但保留必要定义与衔接。每个新术语首次使用时补足含义；分类表不能冒充完整枚举，相关概念不能错误地画成互斥选项。保留01与已认可交互，不新增当天背诵或练题负担。
8. 新建或修订课程交付前，以第1天修订稿为质量样板逐节检查：首次出现的术语能否从正文理解；前置概念是否早于依赖它的解释；定义与短例子能否对应；每段是否新增必要信息；标题与正文是否直接呈现知识、没有作者制作旁白。发现缺项须先修正再交付。自动测试只覆盖可检查的结构与回归，不代替逐节内容审读。
9. 第3–12天以贯穿主线和因果推理优先：问题出现在哪个环节、改变什么条件、为何产生不同后果、机制怎样针对该问题。正文按依赖推进；交互形式随机制选择，路径、版本、资源和时间关系要画清。静态例子也保留推导所需的起点、条件和过程，不能只截最后答案。比较时固定无关条件；结果由小数据与规则产生并解释原因。只补必要概念，用重排与替换改善逻辑，不靠扩充篇幅。
10. 第7天不作为通用交互模板：两种事务边界始终并排，同一按钮共同推进扣款、加款失败与主动回滚；不强制预测或记忆切换前状态。核对失败不自动整笔回滚、已提交不能回滚、整体执行不等于业务正确，以及服务层/InnoDB和第8–10天的联系。所有机制尝试是临时状态，不计分、不写学习记录、不增加完成门槛；条件切换与重置清除本例操作，题干变更时提醒已有回答需重看。
11. 计时在浏览器标签页切换和后台活动时继续，休息由学习者手动暂停。正常刷新/关闭前结算保存，再打开保持暂停；切换学习日、完成课程及本站路线/说明页仍暂停。按实际时间差累计而非计数后台回调，保存不重复计时；保留全部存储key、记录格式、累计用时及旧笔记/作答/进度，测试使用独立记录。
